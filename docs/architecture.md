# Architecture notes

The detailed map of canopy's modules, moved out of CLAUDE.md so it does not count against Claude Code's instruction-file limit. Each section is one area; read the one for the code you are about to touch. When a change makes a section wrong, fix it here.

## Shared-backend mode

Shared-backend mode (see `docs/prd-shared-backend.md`, `docs/deploy.md`): canopy can run headless in a container (`Dockerfile`, `docker-compose.yml`; the port is published on the host's tailnet address from `.env`, and `docker-compose.sidecar.yml` adds a tailscale sidecar for a host that is not on the tailnet; the `tunnel` service, under the compose profile `tunnel` that `.env` turns on with `COMPOSE_PROFILES=tunnel`, is cloudflared with `TUNNEL_TOKEN` for the public name, its ingress `http://canopy:7850` kept in the Zero Trust dashboard, `CANOPY_PUBLIC_ORIGIN` passed to canopy for the origin gate, and Cloudflare Access the only auth in front; `TUNNEL_TOKEN` defaults empty rather than `:?` since compose interpolates profiled services too) as one always-on backend for every client on the tailnet; the tmux server that holds the shells runs in a second container, the `shells` service, off the Dockerfile's `shells` stage (runtime, user, gh, claude, codex, `lib/tmux.conf`, ble.sh and a `~/.bashrc` that sources `shell/bashrc` off the mounted `~/.claude` when the host keeps one, no canopy code, so a canopy rebuild does not move its image and compose leaves it running) as `tmux -S /config/tmux.sock -f /app/lib/tmux-server.conf -D` (foreground; that conf sources the shared one and sets `exit-empty off`), with every mount canopy has since the shells run there (the read-only `~/.config/git` too, for a commit's author and the global ignore) and canopy's `GH_TOKEN` and `GIT_CONFIG_*`, so gh is git's credential helper for github.com in a shell as it is for the server; a change to that service's mounts or env recreates the container, ending every shell, a `list-sessions` healthcheck that canopy's `depends_on` waits for (a `new-session` before the socket exists would start a server inside the canopy container, gone with it), which is what makes a canopy redeploy or crash keep every shell (Phase 4; a host reboot ends the tmux server, and `keepShells` is what brings each shell's terminal and history back after one, not the processes); it runs on the mini since 2026-09-22, as the host user (`bun`, uid remapped by build args) because claude refuses `--dangerously-skip-permissions` as root, with `SHELL=/bin/bash` since `userShell()` falls back to bash off a Mac and a missing shell kills every tmux session at birth. A third service, `stages`, runs the incubator's agents and their checks with no token (see the incubator bullet). `hostOpeners()`/`backendCaps()` in `core/openers.ts` put a `Backend` (`openers`, `sshHost`) on `ScanResult`: when the host is not a mac desktop the server refuses the launcher with `NO_DESKTOP` and the UI hides the launch section. The desktop openers follow the client instead, through a helper: `canopy helper --backend URL` (`core/helperd.ts`, Bun-only: dials `GET /api/helper?name=&platform=&openers=&harnesses=` as a websocket (`harnesses` the ones this helper reads off an intent; an older helper sends none, and `helperRefusal` in `askHelper` refuses it an agent or herdr start on any harness but claude with a 400 saying to update it, since it would drop the harness and start claude with codex's flags), reconnects at doubling waits, runs each intent through `openIn`/`openFile`/`openGroup` here and answers under its id; `localOpeners` finds what is installed through `helperOpeners`; both ends ping every `HELPER_PING` (20s) and give up after `HELPER_DEAD` (60s) of silence, since a backend that dies with its host sends no close frame and the socket would sit half-open forever, the helper believing it is registered and the server offering one that is gone (`staleHelpers` is the sweep, `retire` the helper's own side)) speaks the pure protocol in `core/helper.ts` (`parseHelperQuery`, `parseHelperIntent`, `parseHelperReply`, `reachFrom` which rewrites a backend-local path to `ssh://$CANOPY_SSH_HOST<path>` for the helper, `parseDefaultGateway` off `/proc/net/route`). The server keeps `state.helpers` by name (a newer one under a name replaces the older), lists them at `GET /api/helpers`, broadcasts the list as a `helpers` event on attach and detach, and answers `GET /api/client` with a `ClientInfo` (`address`, `local` = loopback on a mac desktop, `shared` = the address is the container's default gateway, which is what docker's userland proxy hands it for every client, so it tells no browser apart); the open routes (`repos/open`, `repos/openfile`, `workspaces/open`) take `helper` in the body and relay through `askHelper` (`HELPER_TIMEOUT` 20s then 504, a helper's error is a 502), or run on the backend's own desktop for a loopback browser on a mac, else 400 `NO_HELPER`. The browser derives what it can open through the pure, browser-safe `clientCaps` in `core/client.ts` (its `helper` setting first, the one helper at its own address when the address is not shared or loopback, `local` next, else nothing; the arrays it returns are stable references so a `useShallow` selector over it settles) as `capsFor(s)` in the store, and `helperFor(s)` is the name every open call sends; `RepoMenu` gates agent, herdr and the "open in" row by those openers and shows the VS Code `vscode-remote://ssh-remote+$CANOPY_SSH_HOST` link when there is no `code` among them, the workspace buttons in `TopBar` do the same, and `Settings` has the picker ("desktop openers", `auto` or a helper by name) with the address the browser is seen as. Presence (Phase 3) is by browser, not by address, since the proxy collapses them: each browser profile mints a 16-hex id once (`clientId()` in `ui/src/client.ts`, localStorage `canopy.client`) and names itself from the `device` setting or the user agent (`deviceName`/`platformOf` in `core/presence.ts`, browser-safe), and `identity()` puts `client`, `name` and `platform` on the event stream's query and `client` on every shell socket's; the server keeps `state.streams` by SSE controller (`parseStream` validates the query; a stream without a client is no device), folds them into `Device[]` through `devicesOf` (one per id, newest name, oldest `since`, `streams` count) for `GET /api/devices` and the `devices` event (`tellDevices`, debounced 300ms), and `termInfo` adds `viewers` (device names with a socket on the shell) to every `TermInfo`, broadcast whole as a `terms` event by `tellTerms` on every start, join, leave and end; a run keeps `by` (the starting browser's device name, from `client` in the run request) and `RunSheet` shows it. The store holds `devices` and `shells` (the live `TermInfo[]`), `KeptShells.tsx` is the top bar's `⟲ n` chip and popover, there only when a machine going down left shells behind: one row each (repo, how long ago, lines, the agent it had) with restore, "restore + continue" for a claude shell, and forget, while the switch itself is a row in `Settings` since it is the backend's setting and not this browser's; `Shells.tsx` is the top bar's `▸_ n` chip, the shells picker: every held shell (`shells`) with join (`joinTerm`: its tab here, or a new one onto it, its panel opened for a panel shell; a dockless window goes to the shell's own `view=shell&term=` url instead), hide here (`hideTerm`: the tab goes without ending the shell, and the name joins `hiddenTerms`, persisted in the layout, which `reconcileTerms` and `adoptTerms` pass over and `pruneHidden` trims to the live shells) and end; and a repo's agent conversations, both harnesses', through `GET /api/repos/resumable?id=` (`core/sessions.ts`: `agentSessions` merges `codexSessions` (below) with `claudeSessions`, which reads `$CLAUDE_CONFIG_DIR` or `~/.claude` `/projects/<projectFolder(path)>/*.jsonl`, newest first, the first typed prompt, summary and branch off each file's head through the pure `parseSessionHead`; empty for a `host` repo), where resume is `POST /api/repos/resume?id=` `{term, place, session, cols, rows}` (`resumeTerm`: 400 for a bad name or id or a `host` repo, 404 for a conversation not filed under that repo, 409 for a name in use; starts a shell under the browser's name on tmux or a plain pty and types `resumeLine`, `claude <agent flags> --resume <id>` or `codex resume <flags> <id>` by the body's `harness`, in after a beat) and the store's `resumeAgent` adds the tab; tests in `sessions.test.ts` and `server/resume.test.ts`; `Devices.tsx` is the top bar's `⌘ n` chip and popover (platform word, `ago()`, windows, this browser, "in a shell at …" off the viewers), and `adoptTerms` in `ui/src/term.ts` (tested) turns every held shell into a tab on the `terms` event and at load, a panel shell only once its panel is open (`openPanel` adopts too), so a shell opened on one device is a tab on every other; the feed reads `helpers`, `devices` and `terms` events into device and shell lines. Presence labels and never authorizes. `openers.ts` has Linux builders next to the macOS ones (`linuxCommandFor`, `linuxRemoteCommandFor`, `linuxAgentArgs`: kitty `--detach`, `xdg-open`, no Terminal.app) and `openIn`/`openAgent`/`openGroup` branch on `process.platform`, so the helper runs on Omarchy too. `CANOPY_NO_DESKTOP=1` forces the headless behaviour on a mac; `CANOPY_SSH_HOST` names the ssh alias for the VS Code link and the helper's locators; `canopy ui --no-open` skips opening a browser. The launcher (`core/launcher.ts`) stays backend-side and macOS-only by design; the in-browser core (shells, runs, git, search, diffs, history) is backend-host and works anywhere.

The scopes (`scopeOffers`, default first) are the workflow step, the whole workflow and the repo for a flow step's run (`Run.flowStep`, set from the `ActionSpec` by `stepSpec`, with the workflow's `source`), else the repo; step and workflow scopes carry the source and exist only for a bundled or user workflow, since a repo-local one with the same name in another repo is a different file. `POST /api/runs/answer` with `{kind: "allow", remember: {rule, scope}}` goes through `Runner.rememberScope`, which refuses (409) a stage run, a prompt id that is not the one waiting (the console keys its form by prompt id and answers with the id it was shown), a rule not in `rememberOffer` for that prompt, and a rule that does not cover it. It resolves the scope from the run (`scopeOf`: step and workflow apply in every repo with the same source, repo is the run's path, so a reused incubator slug would see an old slug's repo rules if any existed, which stage runs never write; 400 when the run has none), keeps it in `RememberedRules` (`core/remember.ts`, `<config dir>/remembered.json`, written atomically through a temp file and a rename, 0600, and taken into memory only once the write succeeds; a failed forget keeps the rule), broadcasts `remembered`, answers the prompt and `recheck`s every waiting run. `RunCtx.ask` consults the `RememberHook` after `allowAll` and `unattended`, so a retro run and an unattended workflow behave as before. `ruleCovers` refuses a `noRule` prompt and any Bash command `explainCommand` flags outside or `guarded` (it reads the prompt's own command, so codex's `sh -lc` wrapper is gone and a Claude `sh -c` stays opaque); a prefix rule then covers only a simple command it matches (codexrun's `autoAnswer`) that is neither `opaque` nor `runsOther`, an exact rule exactly its command, a bare `Bash` any command that is not `opaque` and whose cwd is inside, an edit tool a change inside that touches no guarded path, and another file tool needs at least one path, every one inside. A matched rule still passes the hook's `inside` (`runsInside` for the command, `pathsInside` for the paths, which real-paths the nearest existing ancestor so a symlink out of the project does not count as inside, and for an edit tool also refuses a real path that is guarded, so `tools -> .git/hooks` does not make `tools/pre-commit` an ordinary file) before the run goes on. A question is never answered, and the step notes `allowed by a remembered rule (<rule>)`. `GET /api/remembered` lists the rules and `POST /api/remembered/forget {id}` drops one; the store keeps them per backend (`remembered`, `loadRemembered` when the inbox opens, the `remembered` event).

## The Library

The non-color tokens (radii, shadows, `--trunk`, and the washes `--wash`, `--wash-strong` and `--well`, tints of `--ink` over transparent) stay on `:root`, shared. The rules are one box deep (the header comment of `styles.css`): only a card, a floating layer (popover, menu, sheet, focused shell, bench), a text field and `.mini.strong` (with the guided panel's primary) have an edge or a fill of their own, and nothing with an edge sits inside another. The dock is columns of tabbed cells (pure `ui/src/grid.ts`, tested). A `DockLayout` is a list of `columns`, each an `id`, a px `width` and its `cells` top to bottom; a cell is an `id`, its `panels` (its tabs, in order), the `active` one showing and a `share` of the column's height, and a column's shares sum to 1. Ids are `c` and a number, one past the highest in use (`newId`). Every operation is pure, and every one but `regroup` gives back the layout itself when it changes nothing, so an action that moves nothing saves nothing (`regroup` always builds a fresh layout with new ids, which is why `arrangeDock` calls it only when the arrangement changes, and `stepPanel` gives null rather than the layout): `place` makes a layout hold exactly the open panels (closed ones leave, a cell whose showing tab left shows the one `nextActive` picks, and each new panel becomes a column of its own side by side or a tab of the active cell as tabs), `moveTo` takes a panel into a cell's middle as a tab or beside it as a new cell above or below or a new column left or right, `moveWithin` makes it a tab of a cell at an index, `moveColumn` and `moveCell` move a whole column along the row or a cell up or down its column, `regroup` makes every panel a column of its own or puts them all in one cell, `stepPanel` moves a panel one place left or right (below), `resizeColumn` sizes a column and `resizeSeam` the boundary between two cells (no cell under 0.1 of its column, the others keeping their shares; `seamRange` gives a seam's two limits and its midpoint), and `rename` swaps one panel id for another in place, which is how `switchCheckout` keeps a panel's place. `normalizeLayout` repairs a layout read back from storage: entries of the wrong shape go, a panel saved twice keeps its first place, widths and shares become finite and positive with no share under 0.1 (`floored`), and an id that is not `c` and one to six digits (`SAFE_ID`), or that repeats, is issued again, since ids become CSS custom property names.

`gridOf` turns the layout into one CSS grid. Each column is two tracks, a 6px seam and the column itself; the rows are the union of every column's cell boundaries, in `fr`, with boundaries closer than 0.001 merged into one line (`MERGE`), so thirds in one column against halves in another leave no sliver of a row. A cell's `grid-area` spans the rows its share covers (a column's last cell reaches the bottom line), and the plan lists each panel's area, its cell and whether it is the cell's showing tab, a strip for every cell of more than one panel, a column seam per column, and a row seam over every cell but a column's first. `gridTemplate` writes each column track as `var(--col-w-<id>, <width>px)` and sets every variable from the layout on each render, so a seam's live write is replaced by the next render rather than outliving a width change; with `fill` (a lone column under the carousel) the column takes the whole dock and its seam no room. `rowsTemplate` makes the rows `minmax(0, …)`, so the grid fits the dock's height and scrolls only sideways. A column id becomes part of a property name only through `cssId` (`columnVar`): every character outside `[A-Za-z0-9_-]` turns into `_` and an FNV hash of the whole id follows (`--col-w-c1-11s3ljt`), so two ids that differ only in those characters never share a name.

The dock never moves a panel's element (`Dock` in `components/Dock.tsx`), since a moved element reloads a preview's iframe and a remount drops a shell. `.dock.grid` holds the panels first, the same keyed children of the same element whatever the layout, sorted by id (`stableOrder` in `ui/src/dock.ts`) and placed by `grid-area` (`placements`); a panel that is not its cell's showing tab is `hidden`, and one the plan does not hold takes no room rather than auto-placing. The strips and seams come after the panels as free elements on the same grid, so their churn never moves one: a `CellStrip` over the top of each cell of tabs (`.cell-strip`, whose tabs are handles too; the cell's panels are padded by `--strip-h` under it), a `.seam-col` down each column's left edge (a `Resizer` that writes `--col-w-<id>` live and calls `resizeColumn` on release, with `follow` on, so once the dock is at its widest and scrolls, the drag moves the dock's `scrollLeft` to keep the seam under the pointer and a cancel puts the scroll back; with nothing scrolled off the left, a shrink still moves the column's far edge instead, as far as the hidden overflow on the right; its arrows step it, Home and End take it to 240 and to the most that fits now (`keyedWidth`), and a key at its limit, or a double-click on a column already at 440, saves nothing), and a `.seam-row` along the top of every cell but a column's first (`RowSeam`, which lays the draft plan straight onto the dock between renders with `paintGrid`, so every area follows the renumbered row lines, and calls `resizeSeam` on release; its arrows move it, Home and End take it to its limits, a double-click splits the two cells evenly, and `aria-valuemin` and `aria-valuemax` are its real limits from `seamRange`; a click that moved nothing or a key at the seam's limit saves nothing, and `pointercancel` paints the layout back). `.dock-corner`, the carousel switch, spans the grid's first row with `justify-self: end` and is not sticky: held to the visible edge it sat on the × of whichever head the edge cut through, so it scrolls with the last column, in the room every head and strip keeps for it, and every panel gear's "carousel" stands in once it has scrolled away. The drag layer renders last. `.dock.grid` and the corner are the only positioned boxes there. Below `PHONE` there is no grid: `placements` gives each panel a CSS `order` in the flat dock, in the layout's order, every panel side by side in the swipe row a phone always had, or in tabs mode (`.dock.phone-tabs`) one strip of every open panel over the one showing, as before phase B. The store's `movePanel` moves a panel one place left or right, from Alt+Shift+Left/Right on a focused head or tab and from the gear's "move left" and "move right". It keeps phase A's flat index: the panel at index `to` of `panels` is where this one heads, and `stepPanel` in grid.ts maps that onto the grid, a tab among its cell's tabs moving within the cell (`moveWithin`, the showing tab kept), a lone column moving as a column (`moveColumn`), a tab heading out of its cell of tabs going no further than the cell's edge (its sibling tabs never move with it, even in a stack), and a cell of one panel in a stack moving up or down its column (`moveCell`). `stepPanel` gives null for a move that changes nothing, and the gear runs it dry, so "move left" and "move right" are greyed out wherever they would do nothing. `moveWithin` is the grid's own op for joining a cell at an index and does not replace it. Dragging a panel's name or glyph, or its strip tab, is a pointer drag (`startPanelDrag`, on the grid only): past `PAN_SLOP` a `.drag-shield` covers the grid so a preview's iframe never takes the pointer, `dropTarget` turns the panel cell under the pointer (`elementsFromPoint`, `.panel[data-cell]`) and `dropZone` into a drop that a `.drop-preview` outlines (`zoneRect`, cut by `clipBox` to the part of the window the dock shows, so a cell scrolled partly out never draws it over the cards; the strip's mark is cut the same way), and letting go calls the store's `dropPanel`. Over a cell's tab strip (`.cell-strip[data-cell]`, checked before the cell under it) the edges and the middle do not apply: `stripDrop` takes the pointer's x and where each tab is drawn to the gap before the first of the cell's other tabs whose middle is at or right of it (after the last otherwise), a `.drop-preview.drop-mark` bar marks that gap, and letting go calls the store's `dropTab`, which is `moveWithin` at that index. So a tab dragged along its own strip reorders, one from elsewhere joins the cell there, and a drop on a strip never splits; back at its own place, showing or not, is no drop and saves nothing. Any drop that changes nothing likewise moves and saves nothing; Escape before letting go, a cancelled pointer, a lost capture, a blur, a context menu, a move with no button held (a release the page never heard) or the dock leaving its grid moves and saves nothing (the phases are `dragStep` in `ui/src/drag.ts`). So does a layout changed from outside the drag (a window taking up another screen class's arrangement, a scan pruning a panel), since the drag's drop cell, like a seam's column and index, is an id the new layout may give to another cell: a store subscription in `Dock.tsx` takes a live drag down as Escape does and cancels every seam drag in progress (`holdSeam`), a row seam painting back the layout it was pressed on and a column seam putting its custom property back. Each gesture lets go of its hook before its own commit, and a seam unmounted mid-drag (its cell closing, the window narrowing past `PHONE`) ends its drag and lets go of it on unmount, so a later layout change never replays a stale paint or width. Escape mid-drag takes the layer down but keeps listening, and the release that follows is swallowed rather than taken as a click; under the slop it ends the press outright. A finger starts a drag by resting on a handle for `TOUCH_HOLD` (350ms, `dragStep`'s `hold` input; one that moves past the slop sooner is scrolling, and the press ends), with a short buzz where `navigator.vibrate` exists. Once a finger holds a panel, `keepStill`, a non-passive `touchmove` listener on each handle (React's are passive, and only a listener there from the touch's start can cancel its moves), keeps the row from scrolling under it, and the long press's context menu is cancelled rather than ending the drag. The gear's move, split and new-column entries still work too. A drop that rebuilds the arrangement it started from is no move (`moveTo` gives back the layout itself, its row shares kept). The gear's "split below the panel on the left", "move to a new column" and "join the cell on the left" make the same drops from the keyboard (`gearDrops`). After a move by keys, and whenever the showing panel changes in a side-by-side dock (opened from its card, back from a pop-out), the panel's head is scrolled into sight (`revealHead`, nearest edge, without smoothing under reduced motion). The rest of a head is left free for panning the dock, and below `PHONE` the dock stays as it was: no handles, no move keys, no move entries and no "pop out" in the gear.

The store keeps `dockLayout` beside `panels`, and `panels` is always `panelsOf(dockLayout)`: columns left to right, cells top to bottom, tabs in order. Every action writes the two together, taking `panels` from the layout (`panelsFor`, the same array when it reads the same, so a move that changes nothing is no change to save). `dockPanel` is the one writer for every way into the dock by hand (its card, a shell, the bench, a task; the load and a backend's connect place the layout themselves): a new panel becomes a column of its own side by side, or a tab of the cell that was showing as tabs, and then shows. `closePanel`, `movePanel`, `dropPanel`, `arrangeDock`, `returnPanel`, `switchCheckout` (through `rename`), the tree's prune and the loader compute the layout first in the same way. Each action reconciles the layout from `panels` before reading it (`laidOut`), so a `panels` set on its own (a test, say) is followed: closed panels leave, new ones join, and a list reordered by hand rebuilds the layout flat, losing its splits. A subscription registered after every other one in the store module is the net for any path that sets one of the two without the other (the gesture cancel in `Dock.tsx` registers later, but only reads `dockLayout` and ends gestures, so the order is safe). The load and a backend's connect already compute `panels` from the layout, so for them it is a fallback; a screen change sets `dockLayout` alone and relies on it, the layout leading and the open set taking its order once it is placed over this window's panels.

`dockLayout` is kept per kind of screen (it is in `SCREEN_LAYOUT`, so `putScreen` writes it to the screen's slot). A window moved to another kind of screen takes up that screen's own arrangement, placed over the panels open here; a screen never arranged starts from the nearest one that was, by the `screenSlots` chain (in practice the last arrangement the main window made anywhere), and keeps it as its own from then on. A screen change never regroups. `arrangeDock` does, and only from an explicit choice that changes the arrangement: the panel gear's "panels side by side" and "panels as tabs" and the Settings page's open-target picker (when it picks the dock or tabs) each call it, which sets `openIn` and regroups the dock into a column per panel or one cell of tabs. The gate compares arrangements, not `openIn` values (`arrangementOf`): `openIn` "tabs" is the tabs arrangement, and "dock", "tab" and "window" are all columns, which is also what lights the panel gear's "panels side by side". A pick whose arrangement is the one already in place sets `openIn` when the value differs and does not regroup, so going from a tab or a window to the dock, or picking the entry already lit, keeps every split and tabbed cell. The picker's tab and window set `openIn` alone (`setSetting`) and never regroup; otherwise `openIn` only decides how a new panel joins. Widths go by panel, not by place: `regroup` itself reuses widths by position, but `arrangeDock`, going to tabs, saves each column's width under the panel leading it (alone in the column's top cell, `leadWidths`) into `panelWidths`, and going to columns gives each new column its lead panel's width from those (and the old columns' leads) straight away, so a panel that leads a column after the regroup takes its width back. A lone column's width is also saved to `panelWidths` when its panel closes or pops out (`claimPanel` goes through `closePanel`) and when a checkout switch onto a sibling already open takes its column away, and `place` reads it for that panel's next column (`widthOf`), so a pop-out coming back keeps its width.

A layout saved before phase B has no `dockLayout`. `loadDock` builds the first one with `fromLegacy` from the saved open `panels` in order (and from this screen class's own slot: a class whose slot holds sizes from before B but no `dockLayout`, while no slot in its chain has one, builds its own rather than taking the flat copy another class wrote after the upgrade, `legacySlot`; a class never visited has no slot and inherits as above): each a column at its own old `panelWidths` width, or, when `openIn` is tabs, one cell at the old tabbed dock's `dockWidth`. `dockWidth` is read only for that and never written, and `panelWidths` stays on as the closed columns' memory. A saved layout is repaired (`normalizeLayout`) and its widths clamped to `PANEL`, and either way the result is placed over the open panels.

The stable DOM has one accepted cost: Tab and a screen reader walk the panels in the DOM's order, sorted by id, not in the order CSS shows them, so after a move the focus order and the visual order differ (WCAG 2.4.3). The strips and seams share it: they come after every panel in the DOM, so a cell's strip is reached after all the panels, where phase A's tabbed dock had its strip before the panel. A reorder is never a DOM move, so the fix cannot be one either; a roving tabindex over the heads, or `aria-owns` on the dock listing the panels, each with its strip and the seams beside it, in `panels` order, is the follow-up.

The carousel (`settings.dockCarousel`, kept per kind of screen like the gear choices; the gear's "carousel" entry and the `.dock-carousel` switch at the dock's top right) puts `carousel` on `.body`: the cards' column (`.main`) goes and the dock is placed in the last grid track by hand, so it does not slide into the emptied one; a column may be as wide as the window less its seam (`dockRoom`); and the row scrolls sideways with `scroll-snap-type: x proximity`, each column snapping at its seam (`.seam-col`, the column's left edge). The row pans only with more than one column; under the carousel a lone column, in either mode, takes the whole dock (`gridTemplate`'s `fill`, with no seam) and does not pan, while with the carousel off it keeps its width and seam. `useCarousel` in `Dock.tsx` does the panning, with the arithmetic pure and tested in `ui/src/carousel.ts`. A drag on a panel head pans once it passes `PAN_SLOP` (6px), and so does one on the dock's background past the last panel, but a drag on the head's name or glyph moves the panel instead (they are its drag handle, `[data-drag-handle]`) and a press on a head's button, link or menu stays theirs (`NOT_PAN`); a touch is left to the browser, which already scrolls the row under a finger. The wheel: a vertical wheel over a head pans; over content only shift+wheel pans, and not where the content scrolls sideways itself by more than a pixel (`overflowsX`, so a wide diff keeps its shift+wheel; the ancestor walk runs only for a shift+wheel, `wheelTake`); a sideways trackpad swipe is the browser's; a ctrl or cmd wheel, which is also how a trackpad pinch arrives, never pans, since it is the page's zoom; and the row takes a wheel only when it can still move that way (`canPan`), so at either end the wheel goes on to whatever is under it. The wheel listener captures, so a terminal in mouse mode never sees a wheel the row took. Ctrl+Alt+Left/Right jumps to the previous or next column's edge (`snapTo` over the column seams' positions, `panelEdges`); the listener captures on window, so while the carousel is on those keys never reach a focused shell. While a panel is over the window (full screen, filling it, or the bench, each a fixed box still inside `.dock`), the wheel, the drag and the keys leave the row behind it alone. On the grid every head keeps 32px of right padding, and every strip 34px, so the switch never covers a close button. With one column (as arranging the panels as tabs makes, or a single panel) the carousel gives it the cards' room and does not pan, and the switch's title says only that; below `PHONE` there is none.

Full screen (a panel's gear, "full screen", beside "fill the window") puts the panel in its fill-the-window mode (`surface-full`) and asks the browser for full screen on `document.documentElement` (`enterFull` in `ui/src/fullscreen.ts`), never on the panel, whose element would have to move and whose gear menus, portals to body, would not show inside it. A browser that refuses (no user gesture) leaves the panel filling the window; one with no full screen at all (iOS Safari, `fullscreenEnabled` false) shows no "full screen" entry in the dock's gear, and a solo window's entry reads "fill the window" (`fullWord`). Every way out ends both: Esc leaves the browser's full screen, which `useFullscreenExit` hears as `fullscreenchange` and drops `surface-full` with it; picking another mode leaves the browser's full screen; closing the panel leaves it, even when the close lands while the browser is still asking; and a tabbed panel hidden by another tab showing (a pop-out returning, say) leaves it and drops back to normal, so it does not come back filling the window. Where the browser has a keyboard lock (Chromium), full screen once granted locks Escape to the page (`lockEscape`), so a shell in the panel gets its Esc, an agent's interrupt: a single Esc inside a shell or a text field is theirs, a single Esc anywhere else leaves at once (the panel's `useLeaveOnEscape`, with `escapeLeaves` keeping text fields while locked), and holding Esc leaves from anywhere, which is how to leave from inside a shell. Every exit and unmount lets go of the lock (`leaveFull`, `unlockKeys`). Without a lock, Esc stays the browser's and leaves at once, as before.

Pop out and back (`ui/src/panes.ts`, the store's `popOut`, `returnPanel` and `claimPanel`, the main window's listener `listenPanes` in `panes.ts`, tested on a stand-in channel and wired to a BroadcastChannel and the store in `App.tsx`, and the pop-out's in `App.tsx`): the gear's "pop out" opens the panel's solo url with `popped=1` in a window named `canopy:pop:<id>` (`popOutWindow`), first, so a blocked popup leaves the panel where it was, then closes the panel and keeps its dock slot in `popped`, an id to index map saved in `canopy.layout` with the panels. Only a window opened that way joins the protocol: "open in a new tab", a shift-click on a card or a typed solo url has no `popped=1` and never takes a panel out of the dock. The windows talk on `BroadcastChannel("canopy:panes")` in five messages, each checked on arrival (`parsePaneMsg`), since any same-origin page can post: `hello` (a pop-out shows its panel; the main window takes that panel out of its dock, `heardHello` then `claimPanel`, which is also how a second main window learns of it), `bye` (on `pagehide`; the main window waits 300 ms, `BYE_WAIT_MS`, before putting the panel back at its slot, so a reloading pop-out's next `hello` calls it off), `return` (the pop-out's "back to the dock", at once), `close` (the panel's own close in a pop-out: the main window forgets the slot, `forgetPopped`, and the window closes, so its `bye` finds nothing to bring back) and `who` (a loading main window's question, which every pop-out answers with `hello`; after 1.5 s, `WHO_WAIT_MS`, the main window takes back every panel that was out when it loaded and that no window answered for, which is how a pop-out killed without `pagehide` gives its panel back). A panel this window pops out comes back after 1.5 s, `HELLO_WAIT_MS`, unless its window says hello first (`popOut` calls `poppedOut`, which the listener watches), since a pop-out closed before it loads sends neither hello nor bye; a slow pop-out whose hello comes later claims the panel again, as one back from a `bye` does. A main window ignores another's `who`, and two main windows each apply the messages to their own `panels`. A pop-out keeps its panel's shells: it takes up its own repo's held panel shells as tabs (`adoptPoppedTerms` through `adoptHere`), and `returnPanel` adopts them back into the dock the way `openPanel` does. On the grid the slot is a hint: `returnPanel` finds the panel that sat after the popped one in the flat list (`rest[slot]`, its old neighbour) before placing, puts the panel last with `place`, then moves it beside the neighbour, as a column of its own just left of the neighbour's column side by side (`moveTo` to the left of its cell, at the panel's `panelWidths` width or the default) or as a tab just before it in tabs mode (`moveWithin`); a split it was part of is not put back, and with no neighbour it stays last. A panel docked again by any road (its card, a shell, the bench, a task, all through `dockPanel`; switching a card's checkout to it; a saved panel shell reopening it at load) or closed loses its `popped` slot, so a later `bye` or load sweep cannot bring back a panel the user closed. One the user docked or closed by hand while it was out is also `recalled`, and the main window ignores a `hello` for a recalled id, so a pop-out left open after its panel was docked from the card does not take the panel again when it reloads. A panel the `bye` timer or the load sweep brought back is not recalled, and a later `hello` claims it again: that is how a pop-out back from the back-forward cache, or one whose reload outran `BYE_WAIT_MS`, gets its panel back instead of showing it twice. Popping the panel out again un-recalls it. `recalled` lives in the main window only and is not saved, so after that window reloads, a stale pop-out answering `who` claims a hand-docked panel again. A popped home panel whose repo leaves the scan loses its slot with the scan (`treeState`), and `returnPanel` brings back no home panel without a repo once the tree has loaded. The loader takes `popped` only as a plain object of finite slots (`poppedOf`), so a hand-edited array cannot turn into panels "0" and "1". Dockless windows strip `popped` from their layout patch along with `panels`, `dockLayout`, `activePanel`, `terms` and `activeTerm`, since their copy is the grove's.
