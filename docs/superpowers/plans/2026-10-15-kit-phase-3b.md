# Kit phase 3, part B: per-cell apply, skill adopt, tools

**Status:** not started.

**Goal:** the kit view fixes one cell at a time, takes over a hand-made skill
folder the way phase 2 takes over a hand-made MCP entry, and shows (and,
where no sudo is needed, installs) the tools `kit.json` lists.

**Spec:** `docs/superpowers/specs/2026-10-15-kit-secrets-phase-3-design.md`,
part B and call 3 of 2026-10-15. OpenClaw stays out (call 4).

## What is there already

- `POST /api/kit/apply {machine, actions}` takes a subset and refuses any
  action that is not in the current plan (`src/server/kit.ts` `apply`, 409).
  Per-cell apply needs no new route.
- A skill cell reads `foreign` ("a dir canopy did not place") when a wanted
  name is present but missing from the target's `.canopy-kit.json` `placed`
  (`src/core/kit.ts` `cell`). Apply never touches it: `link` refuses an
  existing path and `remove` and `relink` refuse anything but a link.
- MCP adopt keeps the old entry for put back (`adoptedFrom` in the ownership
  file, `restore` on the cell). Skill adopt follows the same shape.
- `KitManifest` has no `tools`, and the live `kit.json` has no `tools` block.

## Tasks

### 1. Per-cell apply
- [ ] `cellActions(plan, cell)` in `ui/src/kit.ts`: the plan's actions with
  the cell's agent and name (`link`, `relink`, `remove`, `mcp-set`,
  `mcp-remove`), preceded by that agent's `mkdir` when the plan has one. A
  store cell whose fix is the `pull` gets the `pull` alone.
- [ ] Tests: a missing link, a drifted link with a `mkdir` before it, an MCP
  cell, a cell with nothing to do (empty, so no button).
- [ ] `Kit.tsx`: a cell with actions gets an "apply" button in its sheet that
  posts `{machine, actions}`, then rescans. A 409 says "the plan moved;
  rescanned" and refreshes, never retries on its own.

### 2. Skill adopt and put back
- [ ] `src/core/kit.ts`: a `foreign` cell in a `link` target for a skill the
  store holds says "a hand-made <kind>; adopt moves it aside and links the
  kit's", and gets `restore: true` when `.canopy-kit.json` has
  `adoptedFrom[name]`. The store target and `copy` targets are not adoptable.
- [ ] `KitAction` gains `skill-adopt {agent, name, link}` and
  `skill-restore {agent, name}`. Neither is ever in a plan, the same as
  `mcp-adopt`.
- [ ] `APPLY_SCRIPT` ops: `adopt dir name link` moves `dir/name` to
  `~/.canopy-kit-adopted/<agent>/<name>` (refused when that path exists,
  made 0700), then places the link; `putback dir name` removes the link
  only if it is one, and moves the folder back (refused when the folder is
  gone). `nextPlaced` records `adoptedFrom[name] = <adopted path>` and drops
  it on put back.
- [ ] `KitHub.adoptSkill(machine, agent, name)` and `restoreSkill`, through
  `serial`, refused unless the cell is adoptable (or `restore`) in the
  current scan. Routes `POST /api/kit/skill-adopt` and
  `/api/kit/skill-restore {machine, agent, name}`.
- [ ] Tests on a scratch target: adopt a real folder, a file and a foreign
  link; the destination already taken; put back with the link edited by hand
  (refused, nothing moved); an ssh machine through the fake `onHost`.
- [ ] `Kit.tsx`: adopt and put back in the cell sheet, put back behind a
  confirm that names the folder it brings back.

### 3. Tools
- [ ] `parseKit` takes `tools: {<name>: {check, install?: {darwin?, arch?,
  debian?}}}`, each line a non-empty string, errors per field.
- [ ] `kitscan` reports each machine's `os` (`darwin`, or `ID` from
  `/etc/os-release`) and runs every `check` with a 10 s timeout, in one sh
  script per machine: exit 0 is `ok`, 127 is `missing`, anything else is
  `check failed` with the first line of stderr.
- [ ] Cells with `kind: "tool"`: `ok`, `missing`, `check-failed`, `no-install`
  (missing with no line for this OS). The matrix gets a tools row group under
  the MCP servers.
- [ ] Install: a line with `sudo` as a word is a copy line in the sheet. Any
  other line runs from an "install" button behind a confirm that shows the
  exact line, through `POST /api/kit/install {machine, tool}`, on `onHost`
  with the machine's login shell, then the check runs again. Never part of
  "apply all here". The confirm says the line comes from `kit.json`, which
  any agent can edit.
- [ ] Tests: parse errors, the sudo test (`sudo`, `/usr/bin/sudo`,
  `pseudo-tool` is not sudo), a check that exits 127, an install refused for
  a sudo line and for a tool not in the manifest.
- [ ] Add a `tools` block to `kit.json` in dotclaude (sops and jq are the
  first two). That commit is Eric's.
