# The sweep Implementation Plan (FR-018)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One action, on demand or on a cron, that lists idle shells, chats, finished runs and Eric's own open PRs, and closes the ones he picks or allowed, keeping each one restorable where canopy can.

**Architecture:** A pure planner (`src/core/sweep.ts`) turns facts the server already holds into `SweepItem`s. A `SweepHub` (`src/server/sweep.ts`, deps injected like `RangerHub` and `PrHub`) gathers the facts, rechecks each item and closes it through existing paths (`endTerm`, `runner.stop`, `runner.dismiss`, `PrHub`). Three phases, each shippable: on demand for shells, chats and runs; then the schedule and its inbox ask; then PRs.

**Tech Stack:** Bun + TypeScript strict, `bun test`, tmux, `gh`, React 19 + Zustand, plain CSS in `ui/src/styles.css`.

**Spec:** `docs/superpowers/specs/2026-10-22-sweep-design.md`. Read it first; this plan argues from it.

## Global Constraints

- Gates before a task is done: `bun run typecheck && bun run lint && bun test && bun run build`.
- `src/core/types.ts` and every `src/core/*.ts` the UI imports stay browser-safe: no Bun or node imports.
- Default spans: shell 24h, chat 12h, run 3d, pr 14d, outside 24h. Swept shell and chat records expire after 14 days. A swept PR watch with no reopen is dropped after 30 days.
- Settings default: `{ on: false, cron: "0 4 * * *", spans: <the defaults>, auto: ["shell", "chat", "run"] }`.
- PR close comment, exact: `Closed by canopy's sweep after 14 days with no activity. Reopen it to pick it back up.` (the number is the configured pr span in days).
- Every `/api/sweep*` route needs the `admin` right (page and CLI only).
- Never a candidate: tasks, the ranger, the coordinator, incubator stages, flows in progress, a shell mid-move, a shell with a hand-given label, an agent working or waiting on a permission, a run held by landing or a flow, another author's PR, a PR on an archived repo, an auto-merge or merge-queued PR.
- Tests run on the Mac and the mini: no `ps -o sid`, no GNU-only `stat`/`date` flags. `bun test` pins TZ to UTC, so cron tests pass explicit dates.
- No CSS framework. New UI follows DESIGN.md and the landing queue's and ranger's sheet patterns.
- Commit messages: no backticks. Never push; Eric decides when.

## Review Focus

1. **tmux not answering** (the shells container restarting): the planner must not read "no activity known" as idle. Expected: no shell items at all while `listActivity` throws or the server reports no tmux server. Test in Task 5.
2. **A canopy restart wipes `lastInput`.** Expected: a shell's idle-since is the later of the server's start and its last output, so a restart never makes a just-used shell sweepable. Test in Task 1.
3. **Two devices press "close" on the same items.** Expected: closes run one at a time through the hub's queue; the second press reports `gone` for what the first closed, and nothing is closed twice. Test in Task 5.
4. **A hand-edited `sweep` block in config with a bad cron or negative span.** Expected: `normalizeSweep` falls back to the default for that field and the schedule stays off for a cron `parseCron` rejects. Test in Task 1 and Task 8.
5. **GitHub's `updatedAt` moves because of canopy itself** (its own poll does not, but its sweep comment does). Expected: a PR already closed by the sweep is never offered again, and a failed `gh pr close` leaves the PR open and reports `failed: <gh's last line>`. Test in Task 11.
