# A goal from the top (FR-067, plan 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Start a coordinator from a composer in the manager view, at no repo. The composer takes a goal, attached files, the repos Eric names with `@`, and a model and effort that default to the backend's `coordinate` route. A card may name goal files its worker reads.

**Architecture:**
- The goal's run is held at a fixed anchor repo id, `~goal`. It is built by the server and never in the tree.
- A new multipart route, `POST /api/coordinator/new`, makes the coordinator's folder plus a goal-files folder beside it that outlives the run.
- The brief's last line names the repos and the files.
- A card's `files` give its child `--add-dir` to that folder and a line under its note.
- The UI adds a `GoalComposer` to the manager view, a top-bar entry, and "goal" wherever a run's repo is printed.

**Tech Stack:** Bun, TypeScript (strict, `noUncheckedIndexedAccess`), React 19 + Zustand, bun:test, oxlint.

**Spec:** `docs/superpowers/specs/2026-11-13-goal-from-the-top-design.md` (Part 1). Read it, and `docs/architecture.md`'s "The coordinator" section (`grep -n '^## ' docs/architecture.md`).

## Global Constraints

**Names and limits**
- The anchor id is `~goal`, exactly. Its UI word is "goal". The goal head reads "goal from the top".
- Limits:
  - goal text: at most 20000 characters
  - `repos[]`: at most 20
  - files: at most 10, 25 MB (26214400 bytes) in all
  - card `files`: at most 10 names
- The goal-files folder is `<CANOPY_COORD_ROOT>/goal-files/<run id>/`, mode 0700. It is pruned when its run is not live and its newest file is older than 7 days.

**The route and the agent**
- The route is `POST /api/coordinator/new` with right `operate`. `POST /api/coordinator/start` keeps its meaning (start a goal's cards).
- The CLI verb is `canopy coordinator new "<goal>" [--repo ID]... [--file PATH]... [--model M] [--effort E] [--on NAME]`.
- The agent comes from the backend's `coordinate` role with no repo override: `agentFor(cfg, "", "coordinate")`. `model` and `effort` override it. The harness is always claude, with yolo true and extra "".
- A repo-card start (`POST /api/repos/<id>/run` with action coordinate) keeps working as it does today, `goalRepoLine` included.

**Rules that hold everywhere**
- Never `as any`, never `!` on maps. Imports are relative. A file the UI imports stays browser-safe.
- Tests that shell out use flags both BSD and GNU accept.
- All four gates (`bun run typecheck`, `bun run lint`, `bun test`, `bun run build`) pass at the end of every task that touches code.
- Prose in code comments and docs follows the repo's plain style: no em dashes, active voice.

## Review Focus

1. **A goal whose anchor is not in the tree.** The run must stay on the page after a rescan and must never throw where a run's repo is looked up. The manager view, run sheet head, dock tab label and inbox show "goal". Pinned in Task 4's `runRepoName` tests, and in Task 1's route test that the run's `repoId` is `~goal`.
2. **Two goals at once.** A second top-level goal while one is live must start, while a second coordinator at the same real repo is still refused. Pinned in Task 2.
3. **File names that try to escape.** `../x`, `a/b.png`, an empty name and a duplicate name must land inside the goal-files folder as plain names. Pinned in Task 1 (`goalFileNames`) and Task 3 (route).
4. **A card naming a file the goal does not have, or a card's files on a goal with no files.** `validatePlan` refuses it, naming the card and field. Pinned in Task 1.
5. **A start that fails after the folders exist** (bad repo id in `repos[]`, the runner refusing). Neither folder is left behind. Pinned in Task 3.
