# Run replay, plan 1: the wire on disk, kept for 30 days and redacted (FR-043)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** implemented on private `feat/oct26-batch` 2026-10-27; final batch verification pending; not shipped on `main`.

**Goal:** every run's wire, both directions, is written as it arrives to
`<configDir>/runs/<id>/wire.jsonl` with secrets replaced, the `Run` as it
stood at settle to `run.json` beside it, so a finished run opens read-only
in the sheet after a restart, lists and exports as markdown from the CLI,
and is swept away after 30 days unless its branch or PR is still live.

**Architecture:** a pure redactor (`core/redact.ts`) decides what never
reaches disk; `core/runlog.ts` (Bun-only) owns the folder, the append, the
cut at 50 MB, the gzip at settle, the index and the prune; `DriveCtx.wire`
is the one seam, called by both drivers on every line before they parse,
and the Runner wires it to the run's log and settles the log when the run
ends. The server answers `GET /api/runs/<id>` from memory, else from disk;
the sweep gains a `transcript` kind; `canopy run` lists, shows, exports and
prunes. Replay from the wire, the pure reducers and the fork are plans 2
and 3.

**Tech Stack:** Bun, TypeScript strict, React 19, bun:test. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-25-run-replay-design.md`, the
"Plans" list's item 1. The index is
`docs/superpowers/specs/2026-10-25-software-factory-borrowings-design.md`.

## Global constraints

- The folder is `<configDir>/runs/<id>/`, mode `0700`; its files `wire.jsonl`, `wire.jsonl.gz` and `run.json` are `0600`; the index is `<configDir>/runs/index.json`.
- canopy's own lines in the wire are `{"canopy": "start", at, run, repo, action, harness, argv}`, `{"canopy": "in", at, line}`, `{"canopy": "cut", at, bytes}` and `{"canopy": "end", at, status, error?}`; every other line is the harness's stdout line as read.
- `RUN_LOG_MAX` is 50 MB (`50 * 1024 * 1024` bytes); `RUNS_KEEP` is 30 days and is the `transcript` span's default; `EXPORT_OUTPUT` is 40 lines.
- Redaction happens before any write and again on export, for every nonempty `CANOPY_` value, every applied secret and every caller token. A redacted value reads `<redacted:NAME>`, a caller token `<redacted:token>`, an `--mcp-config` path `<redacted:mcp-config>`.
- A write error ends logging for that run with one note, "transcript stopped: <error>", and never fails the run.
- A run id in a route matches `RUN_ID`, `/^[A-Za-z0-9_-]{1,64}$/`, before any path is joined.
- Nothing of a wire is posted to tailchan, a PR, Linear or Sentry; the hubs read `Run` as today.
- Every file the UI imports from `src/core/` stays browser-safe: `core/redact.ts`, `core/export.ts`, `core/sweep.ts` and `core/types.ts` have no `node:` or `bun` import; `core/runlog.ts` is Bun-only and the UI never imports it.
- Plain words, no em dashes, sentence case headings (the unslop rules apply to docs and commit messages).
- All four gates pass before a task is done: `bun run typecheck`, `bun run lint`, `bun test`, `bun run build`.

## Review focus

Inputs the spec implies and no section of it names. Each has a test in the task that owns the code.

1. The log cannot be opened or written (the config dir is a file, the disk is full): the run starts, runs and ends as it would without a log, with one "transcript stopped" note and no second one (Task 4).
2. A run id with `/`, `..` or a space in `GET /api/runs/<id>`: refused by `RUN_ID` as a 404 before any path is joined, so a request never reads outside `runs/` (Task 6).
3. The index and the folders disagree (a folder removed by hand, an index entry with no folder, no index at all): `listKept` lists what is on disk and `readKeptRun` of a listed id with no folder is null, never a throw (Task 3).
4. A chat with several turns: one log for the whole conversation, an `in` line for every message sent, settled once when the chat ends and not at each reply (Task 4).
5. A run with no result (stopped, failed, or a head-only record the adopt pass wrote) or with its oldest steps trimmed: the export still has its head and says the result is missing, rather than throwing on an absent field (Task 5).

```ts
export interface Secret {
  name: string;
  value: string;
}
/** Empty values are ignored; even a one-character secret must be redacted. */
export const REDACT_MIN = 1;
/** a caller token wherever it appears: `cnp_<kind>_` and 32 random bytes in base64url */
export const TOKEN_PATTERN = /cnp_[a-z]+_[A-Za-z0-9_-]{43}/g;
export const redactedWord = (name: string): string => `<redacted:${name}>`;
/** The values a run's wire must not carry: of `env`, every name in
 *  PRIVATE_ENV, every name starting with CANOPY_, and every key the secret
 *  store applied on this machine (the names under each sink of `applied`)
 *  that `env` holds. Values under REDACT_MIN are left out. Longest value
 *  first, so a value that contains another is replaced whole. */
export function secretValues(env: Readonly<Record<string, string | undefined>>, applied?: Readonly<Record<string, Readonly<Record<string, string>>>>): Secret[];
/** every occurrence of each secret's value replaced by its word, then any
 *  caller token left by `<redacted:token>`; `count` is the replacements made */
export function redactLine(line: string, secrets: readonly Secret[]): { line: string; count: number };
/** the arg after `--mcp-config` (and the `--mcp-config=<path>` form) replaced by
 *  `<redacted:mcp-config>`, then `redactLine` over every arg */
export function redactArgv(argv: readonly string[], secrets: readonly Secret[]): string[];
```

- [ ] **Step 3: Write `src/core/redact.ts`**

Header comment: what the file decides (what never reaches a run's transcript), that it is pure and browser-safe, and that a value split across two lines is out of scope, as the spec says. `secretValues` sorts by value length descending, then name. `redactLine` scans the original input once, choosing the longest literal secret match at each position, then a caller-token match when no known secret matches. export const WIRE = "wire.jsonl";
export const WIRE_GZ = "wire.jsonl.gz";

export const INDEX = "index.json";
export const RUN_ID = /^[A-Za-z0-9_-]{1,64}$/;
export const runsDir = (): string => join(configDir(), "runs");

export type CanopyLine =
  | { canopy: "start"; at: number; run: string; repo: string; action: string; harness: Harness; argv: string[] }
  | { canopy: "in"; at: number; line: string }
  | { canopy: "cut"; at: number; bytes: number }
  | { canopy: "end"; at: number; status: "done" | "failed" | "stopped"; error?: string };

export interface RunLogInit {
  /** the runs folder; the log's own folder is `<dir>/<run id>` */
  dir: string;
  run: Pick<Run, "id" | "repoId" | "action" | "harness">;

/** One run's wire on disk: the folder made 0700 and `wire.jsonl` opened

 *  once through the one open descriptor (`writeSync`), so the file is in
 *  order whatever the harness does. */
export class RunLog {
  readonly folder: string;
  constructor(init: RunLogInit);

   *  bytes the cut line goes and the descriptor closes; later lines are dropped. */

  /** the end line (none after a cut), the close, `run.json` (the Run,
   *  redacted, through a temp file and a rename), the index entry, then
   *  the gzip and the plain file's removal. Once; a second call does nothing. */

}

  /** a log for the run, or null when there is none (then `onError` has
   *  said why); `env` is the run's own environment, over canopy's */

  constructor(opts: { dir?: string; env?: () => Readonly<Record<string, string | undefined>>; appliedFile?: string; now?: () => number; max?: number });
  refresh(): Promise<void>;
  open(run: Run, argv: readonly string[], env: Readonly<Record<string, string>>, onError: (why: string) => void): RunLog | null;

Details the signatures leave open:
- The descriptor is `openSync(path, "a", 0o600)` from `node:fs`; the folder `mkdirSync(folder, { recursive: true, mode: 0o700 })`. A throw in the constructor is the caller's to catch (`DiskRunLogger.open` catches, calls `onError`, returns null).
- The gzip is the streaming one, per the P5 probe run on 2026-10-26 (Bun 1.4.4): `Bun.write(gzPath, new Response(Bun.file(path).stream().pipeThrough(new CompressionStream("gzip"))))`, then `chmod(gzPath, 0o600)` and `rm(path)`. 50 MB took 33 ms with 18 MB more RSS; `Bun.gzipSync` took 51 MB more.
- `index.json` is a JSON array of `KeptRunHead`, rewritten through a temp file and a rename, one write at a time through a module-level promise queue (several runs settle at once).
- A head-only run: `{ id, repoId: start.repo, action: start.action, verb: start.action, progress: "", expectsChange: false, chat: false, harness: start.harness, note: "", status: "stopped", startedAt: start.at, endedAt: now, steps: [], prompt: null }` with the hint's fields over it.
- `readKeptRun` checks `id` against `RUN_ID` first and takes a parsed object only when its `id` is that string.

## Decisions this plan makes beyond the spec

- **Redaction follows the spec's full value set.** Every nonempty `CANOPY_` value is removed, including config paths, addresses and short values, along with private names, applied secrets and caller tokens. This can hide ordinary text that happens to match a value; the plan keeps the spec's privacy rule. The matcher never scans its own replacement markers.
- **P5, answered on 2026-10-26 with Bun 1.4.4.** `CompressionStream("gzip")` exists in Bun; piping a 50 MB file through it took 33 ms and 18 MB more RSS, `Bun.gzipSync` 28 ms and 51 MB. The stream is used.
- **The start line's `argv` is the Runner's, not the driver's.** Both drivers build their command line from pure exported builders (`cliArgs`, `appServerArgs`), so `startArgv` builds the same line for the log and `DriveCtx.wire` keeps the spec's two-argument shape.
- **The transcript span is a full sweep kind.** Items of kind `transcript` go through the plan, the sheet, the ask and the schedule like any other, closed through `dropKept`; `RUNS_KEEP` lives in `core/sweep.ts` beside the other spans since that is what reads it, and `canopy run prune` applies the same `spans.transcript`. A stored config from before this kind gets `transcript` in `auto` once (`normalizeSweep` tells by the missing `spans.transcript`); any later save keeps the user's list.
- **What holds a transcript back.** The spec's "branch still in the landing records or PR open" is `heldRuns` (every landing record's branch id and latest run id) and `livePrs` (every PR watch whose state is open or not yet read), matched on the head's `id` and `origin`.
- **The adopt pass runs under the flows lock** and builds a head-only `run.json` from the wire's start line with the landing record's verb, note, session and branch over it. The flows store holds a step's `runId` and `session`, never a `Run`, so it adds nothing; a run with no record is head-only.
- **Call 6 (stage runs):** logged like any run with the same cap, the spec's default. A coordinator's chat too; the ranger is a session, not a run.
- **Call 7 (the export's home):** nothing is written anywhere but where `--out` says; a `docs/runs/` folder in a repo is Eric's to add later and needs nothing here.
- **`GET /api/runs/<id>` answers a live run too**, so `canopy run show` and the page's `loadKeptRun` work before and after a restart with one call. It is already off the coordinator's lane, which allows `/api/runs` exactly.
- **`canopy run` with no words lists the kept runs**, since `show` and `export` need an id and nothing else prints one.
- **The export's prompts are their settle notes** ("allowed: Bash git push" as a quote), since the prompts themselves live in the wire and folding it is plan 2.
- **The sessions view has no run rows today** (it lists shells and tabs), so the spec's link from it is not in this plan; the costs view's run rows and the landing view's branch links carry the kept sheet.
- **`core/redact.ts` is its own file**, not part of `runlog.ts`, so the export (pure) and the UI could import it without pulling `node:fs` in.
