# Health Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Canopy shows which of its own pieces, and later which of a repo's declared checks, are broken, heals the safe ones with backoff, and escalates the ones that keep failing.

**Architecture:** A pure model (`src/core/health.ts`) holds states, transitions, backoff and the summary. A server hub (`src/server/health.ts`) owns the checks, polls probes, runs heals, broadcasts a `health` event on change and serves `/api/health`. Phase 1 registers canopy's own pieces (mostly adapting status that exists). Phase 2 adds per-repo checks read from `.canopy/health.json` and canopy's config, plus an adaptive card fact and a panel section. One `HealthList` component renders in a top-bar popover, a reserved `/health` dock panel and a `?view=health` page.

**Tech Stack:** Bun, TypeScript strict, React 19, Zustand, `bun:test`.

**Spec:** `docs/superpowers/specs/2026-10-12-health-design.md`

## Global Constraints

- `src/core/health.ts` and `src/core/types.ts` stay browser-safe: no Bun or node imports.
- Timings: `HEAL_MAX` 5, `RESET_AFTER` 5 min, backoff 1 s doubling capped at 60 s, `HISTORY_MAX` 20, `FOLLOW_SILENCE` 60 s, broadcast debounce 250 ms.
- Probe timeouts: `http` 5 s, `command` 30 s, `compose` 10 s, tmux 5 s.
- Repo `command`, `compose` and `fix` run only in own, local, non-seed repos. `auto` is honoured only in own repos.
- No CSS framework; styles go in `ui/src/styles.css`, one box deep, facts as coloured text.
- Gates before done: `bun run typecheck && bun run lint && bun test && bun run build`.
- Do not commit (the user's CLAUDE.md: commit only when asked). Steps that say "commit" in the template are skipped.

## Review Focus

1. A tailchan stream that stays open with no bytes for over 60 s must redial, and a stream fed only `: ping` comments must not. Test in Task 2.
2. A check whose heal keeps failing must stop at 5 heals, go `gave-up`, DM once, and not loop. Test in Task 1 and Task 3.
3. A cloned (not own) repo's `.canopy/health.json` with a `command` or `fix` must run nothing. Test in Task 11.
4. A probe that hangs must fail at its timeout, not wedge the poll loop (the next tick must still run). Test in Task 3 and Task 12.
5. A backend with no `/api/health` (an older build) must leave the chip absent, not throw. Test in Task 7 (the store's catch).

- Produces (health.ts):
  ```ts
  export const HEAL_MAX = 5; export const RESET_AFTER = 300_000; export const HISTORY_MAX = 20;
  export interface HealthTimings { base: number; cap: number; resetAfter: number; healMax: number }
  export const HEALTH_TIMINGS: HealthTimings;
  export interface ProbeResult { ok: boolean; why?: string; detail?: string; off?: boolean }
  export function healDelay(fails: number, t?: HealthTimings): number;
  export function newCheck(def: { id: string; label: string; scope: HealthScope; heal: HealMode }, now: number): HealthCheck;
  export function observe(c: HealthCheck, r: ProbeResult, now: number, t?: HealthTimings): { check: HealthCheck; action: "heal" | "escalate" | null };
  export function healFailed(c: HealthCheck, why: string, now: number, t?: HealthTimings): { check: HealthCheck; action: "heal" | "escalate" | null };
  export function manualHeal(c: HealthCheck, now: number): HealthCheck;
  export function summary(checks: readonly HealthCheck[], now: number): { level: "ok" | "warn" | "bad"; word: string; title: string; count: number };
  export const isBad: (c: HealthCheck) => boolean; // down or gave-up
  ```

Rules for `observe`:
- `off: true` gives state `off`, why null, fails 0, nextHeal null.
- ok: state `ok`, why null, `lastOk = now`; fails reset to 0 when the check has been ok since at least `resetAfter` ago or the previous state was `gave-up` or `unknown`. A pass while `healing` keeps `fails` (a heal that worked once may not stick) until `resetAfter`.
- fail on `auto` with state not `gave-up`: state `healing`, `nextHeal = now + healDelay(fails)`, action `heal`. Fail while `gave-up` stays `gave-up`, no action.
- fail on other modes: state `down`, nextHeal null.
- `history` gets `{at, state, why}` only when state changes; capped at `HISTORY_MAX`, oldest dropped. `since` moves only on a state change.

`healFailed` (a heal ran and the re-probe still fails): `fails + 1`; at `healMax` state `gave-up`, nextHeal null, action `escalate`; else `healing`, nextHeal `now + healDelay(fails)`, action `heal`.

`manualHeal`: fails 0, state `healing` if it was `gave-up` or `down`, nextHeal null.

`summary`: leaves out `off`. bad = any `isBad`; warn = any `healing`, or any `unknown` with `now - since > 60_000`; word: bad → `${n} down`, warn → `${n} healing`, ok → `ok`. `count` is the bad or warn count. `title` lists the labels of the counted checks.

### Task 3: The health hub

**Files:**
- Create: `src/server/health.ts`
- Test: `src/server/health.test.ts`

**Interfaces:**
```ts
export interface CheckDef {
  id: string; label: string; scope: HealthScope; heal: HealMode;
  every?: number;                       // ms; with probe, polled
  probe?: () => Promise<ProbeResult>;
  timeout?: number;                     // ms, default 10_000
  doHeal?: () => Promise<void>;
}
export interface HealthHubDeps {
  broadcast: (ev: ServerEvent) => void;
  onGaveUp?: (c: HealthCheck) => void;
  now?: () => number;
  timings?: HealthTimings;
  debounce?: number;                    // ms, default 250
}
export class HealthHub {
  constructor(deps: HealthHubDeps);
  add(def: CheckDef): void;             // replaces a def with the same id, keeping its HealthCheck
  remove(id: string): void;
  has(id: string): boolean;
  report(id: string, r: ProbeResult): void;
  probeNow(id: string): Promise<void>;
  heal(id: string): Promise<HealthCheck>;   // throws HealthError(404|409)
  list(): HealthCheck[];                // sorted: scope canopy first, then by id
  handle(req: Request, url: URL): Promise<Response | null>;
  stop(): void;
}
export class HealthError extends Error { constructor(readonly status: number, msg: string) }
```
Behaviour:
- `add` with `probe` and `every` starts an interval; a tick is skipped while the previous probe runs. The first probe runs at once.
- A probe is raced with its `timeout`; a timeout is `{ ok: false, why: "timed out" }`; a throw is `{ ok: false, why: err.message }`.
- After `observe` returns `heal`, the hub schedules `runHeal` at `nextHeal`. `runHeal` calls `doHeal` (a throw counts), then the probe again (or, with no probe, waits for the next `report`; it then treats the next failing `report` as `healFailed`). A failing re-probe calls `healFailed`; `escalate` calls `onGaveUp` once.
- `heal(id)`: 404 unknown; 409 when mode is `self` or `none`, or when there is no `doHeal`; otherwise `manualHeal` then `runHeal` now.
- Every change schedules a broadcast; the broadcast sends `{type:"health", checks: list()}` only when its JSON differs from the last sent.
- `handle`: `GET /api/health` → `{ checks }`; `POST /api/health/heal?id=` → the check, or `{error}` with the status.
- `stop()` clears every interval and timeout.

- [ ] **Step 1: Failing tests:** add + report gives the check in `list()`; a polled probe runs at once and again after `every`, never overlapping (a probe that takes 3×every runs once in that span); a hanging probe times out and the next tick still runs; an auto check failing → doHeal called after 1 s (`timings.base` 10 ms in tests) → still failing 5 times → `gave-up`, `onGaveUp` called once; a heal that throws counts; the event is broadcast once for two identical reports; `heal` on a `self` check is 409, unknown 404; `GET /api/health` shape; `stop` leaves no timers (the test ends without hanging).

- `http`: `fetch(url, { signal: AbortSignal.timeout(5000), redirect: "manual" })`; ok on `expect` or 200–399; detail `${status} in ${ms}ms`.
- `port`: `Bun.connect({ hostname, port, socket: { open(s) { s.end() } } })` raced with 5 s.
- `task`: status `running` ok; `backoff` → healing flag; `gave-up` → gaveUp flag; `failed`/`stopped`/`idle` → fail.
- `compose`: `docker compose [-f file] ps --format json <service>` in `repo.path`, 10 s; parse one JSON object per line (or an array); ok when `State === "running"` and `Health` is `""` or `"healthy"`.
- `command`: `sh -c <run>` in `repo.path`, 30 s, exit 0 ok; `why`/`detail` the last non-empty output line.
- heal: `fix` → `sh -c <fix>`; else task → `restartTask`; compose → `docker compose restart <service>`; else none.
- Blocked checks are added with no probe and reported `{ ok: false, why: blocked }` and heal `none`.
- Heal mode: merged `heal` ?? `"button"`; `auto` only when own.
