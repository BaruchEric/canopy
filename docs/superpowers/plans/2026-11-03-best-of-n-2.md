# Best-of-N, plan 2: profiles per member, two reviewers, coordinator cards and the costs fold (FR-033)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** implemented 2026-11-03 on branch `fr-033-plan-2`, merged to `main` and live-checked the same day. See the results under the live check.

**Goal:** Give each member of a group its own agent profile, let a group ask two reviewers who must agree on the winner, let a coordinator card fan out into a group and settle on the group's word, fold a group into one line in the costs view, and show which files the members share.

**Architecture:** Plan 1's shapes stay: a member is an ordinary branch run, the group record is `landing/groups/<id>.json`, `review` keeps its shape and a second optional field holds the second reviewer. Pure rules go in `src/core/group.ts`, `src/core/coordinator.ts` and `src/core/costsheet.ts`; `GroupHub`, `CoordinatorHub` and `startGroup` call them.

**Tech Stack:** Bun 1.4.2, TypeScript 7.0.2 with strict checks, `bun:test`, React 19.3.0, the existing HTTP API, landing queue, and cost ledger.

**Spec:** `docs/superpowers/specs/2026-10-25-best-of-n-design.md`

## Decisions this plan makes beyond the spec

- `reviewers` stays optional on the record and `secondReview` sits beside `review`, because reshaping `review` into a list would break plan-1 records, the group sheet and `ParentLine`.
- `profiles` takes null for "the repo's job route", because the pre-flight's first choice is the repo's default and a profile named `default` may not exist. The CLI spells it as an empty name.
- A member's fix run uses that member's profile. Fixing a Codex member with the default route would blur what the compare is comparing.
- A group card weighs its `times` against `COORD_AT_ONCE`, since the cap counts children working and a card of three is three children. A card that does not fit is passed over, as a full repo's card is, so a later single card may go ahead of it.
- A group card's members start `low`, as the spec says for every group, unless "start anyway" released the card, which starts it `interactive`.
- A group card never auto-lands and never opens a PR. Call 4 holds for cards, and `startCoordChild` opens no PR for a plain child either.
- A group card settles `done` on `winner picked` or `landed`, and `failed` on `needs you` or `dropped`, matching how a sent-back child settles. A settled card does not reopen when Eric picks later, as a settled child's card does not.
- A card's note reaches a group as written. `issueNoteFor` stays off the card path, as it is for a plain child.
- The costs fold gets its "best of N" from the groups the page holds, not from counting runs, because fix runs carry the group too.
- Codex members for `propose`: the spec's refusal stays (the 2026-11-03 default for question 6). `reviewers` stays one by default and `reviewers: 2` is opt-in (the default for question 7).
