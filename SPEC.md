## What it is

A workbench for building software with Claude across every repo and machine you have: a live board of every git repo under a folder, shells that outlive the page, and Claude Code run as shells, jobs, chats and workflows. Web UI and a full CLI.

## Who uses it

One developer (the owner) across a laptop, an always-on Linux backend, a tablet and a phone, all on one tailnet. Agents use it too: Claude sessions run inside its shells and drive it through the CLI, the HTTP API and `canopy mcp`, an MCP server over that API with the token the session holds. It is not built for teams. A public name is served only behind an authenticating proxy (Cloudflare Access). The proxy is still needed with caller tokens on: they guard what a call may change, but reads stay open and canopy has no sign-in for reading, so without the proxy anyone who reaches the name can read everything canopy shows.

## Stack and versions

- Bun 1.4.2 runs the server, the CLI and the tests (`bun test`).
- TypeScript 7.0.2, `strict` in both `tsconfig.json` and `ui/tsconfig.json`.
- React 19.3.0, Zustand 5.0.15, Vite 8.3.2 with @vitejs/plugin-react 6.1.1 for the SPA; a second Vite build makes the service worker (`ui/sw.ts`) into `dist/web/sw.js`.
- @xterm/xterm 6.0.0 for shells; tmux on the backend keeps them alive.
- ai 7.0.127 and @ai-sdk/gateway 4.0.103 for commit message suggestions.
- oxlint 1.86.0 for lint, configured in `.oxlintrc.json`; a hook called after an early return fails lint (`react/rules-of-hooks`).
- Plain CSS in `ui/src/styles.css`; no CSS framework.
- Instrument Sans and JetBrains Mono as bundled variable fonts (@fontsource-variable 5.3.0), so a page never fetches a font.
- git, gh and the `claude` CLI are shelled out to, never linked.
- age-encryption 0.3.1 seals the secret store's values; @simplewebauthn/server 14.0.3 and @simplewebauthn/browser 14.0.0 are its passkey gate.

## How it is built and run

```
bun install
bun run typecheck
bun run lint
bun test
bun run build
bun link
canopy ui ~/dev
```

- Development: `bun run dev` (API on :7850) and `bun run dev:web` (Vite on :7851, proxying `/api`).
- Production: the Bun server on :7850 serves the built `dist/web` (the page, `sw.js`, `manifest.webmanifest` and `icons/`), so a stale build shows a stale UI.
- Shared backend: docker compose (`canopy`, `shells`, `stages`, `coord` (the coordinator's runner, always up, used only once `.env` sets `CANOPY_COORD_SOCKET`, `CANOPY_COORD_API` and `CANOPY_COORD_PORT` and canopy enforces caller tokens, its lane held on that port's own listener), `coord-proxy` (the coordinator's egress proxy, its one way to the internet, which tunnels to Anthropic's names alone), `secrets`, and `tunnel` under its profile). Deploy committed `main` with `bun run redeploy`; `bun run redeploy status` says what is running. From the Mac it goes to the mini unless a backend is named (`desoto`, or `all`). See `docs/deploy.md`.
- Run `bun test` with `SHELL=/bin/bash` when an interactive zsh config slows shells down.

## Data and state

- Config, workspaces, sources, agent and launch settings, the capacity governor's holds, and the archived, starred and harness repo lists: `~/.config/canopy/config.json`, or `$CANOPY_CONFIG_DIR`.
- `providers/<id>.json` next to it: a Claude Code provider, a settings file written by hand (its `env` block names the gateway: `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_MODEL`) and passed as `--settings` to every Claude start on a route that names the id; the config keeps only the id, never the file's values.
- Next to it: `bin/canopy-mcp.js` (in compose, the MCP bundle copied at each backend start for the shells container's `canopy` launcher), `tmux.sock` (the shells' tmux server), `shells/` (kept-shell snapshots), `pastes/` (images pasted into shells and design-mode pictures, kept 7 days), `callers.json` (the token hashes of every signed-in page, CLI, helper, shell and the ranger, 0600), `push/vapid.json` (the web push key pair as JWK with its `mailto:` subject, 0600, made on the first start) and `push/subscriptions.json` (one entry per browser that turned push on, with its endpoint and keys, 0600, written through a rename) and, written by `canopy auth login` and `canopy helper --pair`, `token-<host>-<port>` and `token-helper-<host>-<port>` (0600), `tasks/` (state, which holds a worktree task's folder and ports, and logs), `ranger/` (the always-on agent's conversation, wakes and brief), `builds/` (installed releases and PR worktrees), `worktrees/<repo key>/<id>/` (branch runs' worktrees), `worktrees/<repo key>/warm-<n>/` (prepared worktrees for the next branch run) and `worktrees/<repo key>/warm.json` (the pool record, written only by the flows-lock holder), `trees/<repo key>/<slug>/` (worktrees kept by hand, one per branch, FR-051; the `trees/` folder is scanned as a source of its own, so each tree is a card) and `trees/<repo key>/trees.json` (their record: branch, base, port, state, whether the tree follows its base and the base commit it last synced to, why a merge or sync stopped), `scenarios/<repo key>/` (a repo's holdout scenarios, one markdown file each, written by hand and by `canopy scenarios add`; never synced with the repo), `runs/<id>/` (`wire.jsonl.gz`, both directions of the run's wire with secrets redacted, cut at 50 MB, and `run.json`, the run as it ended; `runs/index.json` lists them; kept 30 days by the sweep's transcript span, longer while the branch is in `landing/` or its PR is open), `landing/` (`runs/<id>.json` per branch run with its latest sort, `groups/<id>.json` per best-of-N group, `queue/<repo key>.json` per repo and `notices.json` for the queue's quiet lines, all written only by the server holding the flows lock), `prs/` (`<branch id>.json` per PR a branch run opened, written only by the server holding the flows lock), `work/` (`<id>.json` per work item: title, state, the runs, branches, PRs and events that served it and its notes, written only by the flows-lock holder and never synced between backends), `sweep/` (`chats.json`, the chats the sweep stopped, kept 14 days so each can be resumed, and `log.json`, the newest 50 closes; a shell the sweep closes leaves its snapshot in `shells/`, kept 14 days), `triggers.json` (the trigger rules, written by hand, naming secrets only by their environment variable; schedule rules add `cron`, `repo`, `only` and `land`, while a github or forgejo rule’s poll cron and write switch live there too), `triggers/events.json` (hook, polled issue and schedule events, written only by the server holding the flows lock) and `triggers/digest.json` (the triggers' last daily line and when it last came due, written by the same server), `library/<root-hash>/` (the project library, with `sync.json`, the Library sync's stamps, written only by the canopy server, and `sync-backups/`, the newest 10 copies of the files a sync replaced), `costs/<YYYY-MM>.jsonl` (the cost ledger: a line per run reply, voice call and dictated clip), `capacity.json` (the last usage-limit hit per harness, retained across restarts, with no credential), `notes.json` (quick notes and reminders, FR-020: one array of notes, each with its text, repo, due time, and when it was made, delivered to the inbox and done; written whole by any server on the config dir, while a reminder is delivered only by the one holding the flows lock), `clips.json` (the clipboard, FR-054: the pinned copies and the newest 200 others of the last 14 days, each with its text up to 16,000 characters or a file's name, type, size and sha-256, its source, place and device and how often it was copied; 0600, written whole through a rename by any server on the config dir) and `clips/<id>` (a file clip's bytes, up to 25 MB each and 512 MB for the unpinned together; folder 0700, files 0600), and `prices.json` (optional, written by hand: the prices that turn usage into estimates).
- In a repo: `.canopy/tasks.json`, `.canopy/workflows/`, `.canopy/workflows.json` (which workflow steps a person releases by hand in this repo, read at HEAD), `.canopy/spec.json`, `.canopy/gates.json` (the landing queue's gates, the setup line that new worktrees and tasks in a checkout with no node_modules run, and default warm count), `.canopy/scenarios.json` (the scenarios' default run line, judge, minimum and timeout) and `.canopy/review.json` (what lands on its own and what needs an approval), all checked in by that repo's owner.
- Per browser: preferences (including the harness-share warning line and the push switch), open panels, shell tabs and the week the harness notice was noted in localStorage (`canopy.harnessSaid`); the service worker's cache, `canopy-<build>`, holds the page shell and hashed assets, never `/api` or `/library`, and a share from the phone's share sheet waits in `canopy-share-<ms>-<rand>` (its words and files, no token) until the page keeps it on the clipboard and deletes it, or an hour passes.
- Runs live in server memory; the last 60 finished ones stay until a restart, and every run's record is kept under `runs/` for 30 days, from where `GET /api/runs/<id>` and `canopy run` read it after a restart, and the run sheet replays it from its wire (`GET /api/runs/<id>/replay`). A finished run forks from a step of that replay (`POST /api/runs/fork`, `canopy run fork`) into a new branch run cut from the original's base; a Claude fork resumes a copy of the original's transcript cut after the step, written mode 0600 under `~/.claude/projects/<fork worktree slug>/<new id>.jsonl` for the fork's start and removed when it ends. A branch run's record and its landing queue entry outlive a restart in `landing/`. A coordinator run carries `held` (Eric held the goal, so no card starts) and its cards in `tasks`: each card has `equip` (a loadout name, plus Eric's `model`, `effort`, `skills` and `mcp` overrides), `workflow` and `workflowRepo`, `after` (card ids it waits for until each has landed), `flow` or `run` or `group` for its child, and `branch`. Cards die with the run.
- Session history is read from claude-history's CLI (`--json`), never its sqlite file.
- The secret store: `secrets.json` in the private Forgejo repo `eric/secrets`, its values sealed with age and the file signed. On the mini the `secrets-data` volume holds the checkout, the keys, `passkeys.json`, `audit.jsonl`, `applied.json` and `proposals.json` (what waits for an approval, still sealed). On every other backend, next to the config: `secrets/` (a pulled copy), `secrets-config.json` (the pinned key and remote), `secrets-key.age` (that machine's passphrase-wrapped key) and `secrets-applied.json`. On a Mac the login Keychain holds that passphrase too (service `ca.beric.canopy.secrets-key`), only after `canopy secrets unlock --keep`.
- `run-tools/<id>.settings.json`, 0600, only while a run started with a loadout (FR-065) lives: the run's one `--settings` file, the provider's settings with the loadout's `skillOverrides` (user skills) and `enabledPlugins` (plugins turned off whole) laid over. Deleted when the run ends, stops or fails to start. The loadouts themselves live in `~/.claude/kit.json` (`loadoutBase`, `loadouts`), not in canopy's config; a run keeps what it was given as `equip` in its `run.json`.
- `run-tools/<id>.mcp.json`, 0600, only while a run holds canopy tools or a loadout's servers: the one file that carries a `run` token, deleted when the run ends. `canopy-tools.md` next to the config replaces the brief those runs read.
- `run-tools/flow-<flow id>.settings.json` and `.mcp.json` (the second only when the loadout has servers), 0600: a coordinator's card flow's loadout (FR-065), written before its first step starts and given to every step's run. They outlive each step's run and a restart (the boot sweep leaves `flow-*` files), so a stopped flow picked up again still has them, and are removed when the flow ends done or failed, or is dismissed or pruned, or when its start fails.
- Agent plugins (FR-064) are the agents' own files, never canopy's: `~/.claude/settings.json` (`enabledPlugins`, `extraKnownMarketplaces`), `~/.claude/plugins/installed_plugins.json` and `~/.codex/config.toml`, written by `claude plugin` and `codex plugin` on each machine. The one exception is codex's switch: canopy rewrites the `enabled` line in a plugin's own `[plugins."id"]` table of `config.toml`, keeping the file's mode, and puts the old bytes back when codex's list does not then follow. The plugins view commits and pushes dotclaude's `settings.json`, alone, on the machine that commits it, with a message canopy writes. On the mini the backend runs `claude plugin` with `HOME` at `CANOPY_HOST_HOME`, so the paths claude records are the host's. canopy keeps a machine's catalog in memory for 10 minutes and nothing on disk. Which agents it manages is `plugins` in the kit's `~/.claude/kit.json`, and the machine that commits dotclaude's shared `settings.json` is `machines.<name>.commits`.
- No database of its own: git and the files above are the state.

## Decisions

- 2026-08-03: Shell out to `git` and parse porcelain v2, because the same call then runs locally or over ssh for a remote repo.
- 2026-08-24: Drive the user's own `claude` binary over stream-json, not the Agent SDK, because jobs must run on the user's Max login and settings (the SDK was tried and rolled back).
- 2026-10-26: canopy's MCP server uses the existing line JSON framing and the caller's own API token, because the small stdio protocol needs no SDK or second rights model. The shells image carries a launcher for its bundle on the config volume.
- 2026-08-24: No CSS framework; one stylesheet of `light-dark()` tokens, because themes only flip `color-scheme`.
- 2026-09-11: The devhub library moved into canopy, because one engine and one dashboard beat two copies of the data.
- 2026-09-21: Shells are tmux sessions on canopy's own server, because a shell must outlive a reload and a canopy restart.
- 2026-09-22: Headless shared backend in containers, with shells in a container of their own, because a redeploy must not kill open shells.
- 2026-09-24: Peers sync over git only, pull-only and fast-forward only, because work should move between machines through commits, never file copies.
- 2026-10-09: canopy takes only the doc half of the shared spec and keeps its design system in `ui/src/styles.css`, because its own palettes and tokens predate the shared DESIGN.md and differ from it.
- 2026-10-16: Every API call carries a caller token with rights (read, plan, operate, shell, admin, helper), checked at the top of `route()`, because a bare `curl -X POST` from a run must not be able to start or stop a run. It ships in `log` first, then `enforce`.
- 2026-10-14: Secrets live in one signed, age-sealed file in Forgejo, written only by a service on the mini behind passkeys, because a value must never sit in a container that shares the shells' namespaces or in a repo canopy syncs.
- 2026-10-20: Voice runs on ElevenLabs' Realtime API with the browser on the socket and the server only minting a 60-second client secret, because audio then never passes through canopy and the key never reaches the page. Its tools only read and navigate, because a misheard word must not commit, push or answer an ask.
- 2026-10-20: GPT-Live is a second voice engine beside ElevenLabs, with its own key (`CANOPY_LIVE_KEY`) and the page picking per browser. It has no client secret a page could open a session with, so the backend takes the page's WebRTC offer to OpenAI and hands back the answer; audio still never passes through canopy and the key never reaches the page. Its tools run on the Responses backend it delegates to, and the page answers them, as with Eleven.
- 2026-10-20: Dictation into fields and shells records in the page and transcribes on a backend through `CANOPY_TRANSCRIBE_URL`, the incubator's speech model, because the ElevenLabs voice key has no speech-to-text permission and the mini already serves Whisper through LiteLLM. The page uses home's model, else the first online backend with one.
- 2026-10-26: The harness repo list is explicit config, seeded once from a local `package.json` named `canopy`; later scans never guess again, since the list is a mark Eric controls.
- 2026-11-02: A start the capacity governor holds waits in its owner's own record (a queued trigger event, a coordinator card, a parked flow, a PR watch, a landing entry), not in a queue of the governor's, because each of those already outlives a restart and says why it waits.
- 2026-10-20: Costs take Claude's dollars from claude-history and keep a per-backend ledger for the rest, with no built-in prices, because the archive already counts every Claude session and only Claude reports dollars; the others are usage until a `prices.json` says what it costs.
- 2026-11-03: A run's token rides in a 0600 file its MCP server reads, off by default and never in the agent's env, because the agent's shell can read env and a file can die with the run; the handlers hold the limits, since that shell can read the file too.
- 2026-11-06: A repo panel shows one section at a time behind a rail of tabs, with the repo's summary beside them in a wide panel, because fourteen stacked sections were what made a panel crowded. The stack stays one gear entry away for anyone who wants several open. Words are in Instrument Sans and only what is read a character at a time is mono. `--ui` lifts the type on wide and ultra HD screens, because 12px at 1x on a 7680px screen is what every saved zoom was working around, and those zooms were scaled back once so sizes hold. The Library keeps devhub's markup and takes the same look through `lib/devhub/theme.css`, its summary and controls in a rail like a wide panel's, because rewriting its editors in React was never the point.
- 2026-11-07: The clipboard keeps copies on the backend, gated at operate for reads too, and its event carries ids only, because the event stream reaches every signed-in caller and a copied line can be private. Text shaped like a key or a password is never kept, and nothing is recorded from a paste, a password box, a shell's screen selection by the page or the Secrets view. Tailchan's #clipboard is shown beside it and never copied into it. A file clip's bytes go out as an attachment with nosniff and a sandbox CSP, as octet-stream unless their type is on a short list, and the page draws an SVG only through an image and never opens SVG or HTML in a tab, because a blob or a link in canopy's origin would run its script with the page's token in reach. A paste or a drop counts only inside the clipboard's body, never on the document or in a shell.
- 2026-11-07: Right-click menus are one page-wide host that answers only where canopy has something to say, and leaves the browser's menu on Shift, in text boxes, shells, pictures and the Secrets view, because spelling, paste and a shell's own copy belong to the browser and the terminal, and a menu must never read a secret or a shell's screen. They never answer an ask or a permission, so an approval stays a deliberate act in its own row.
- 2026-11-09: A caller with no token reads nothing but a short open list (the page's own files, `/api/auth`, `/api/about`, `/api/going`, the pairing routes, the Library's frame), because on an enforcing backend it could fetch any repo file, an `.env` included, through `GET /api/repos/raw`, and after that was closed it still read every live run's steps, the notes and the work items. `read` now means any token. Everything read out of a repo, a run read by its id, a shell's screen and tailchan take a hand's token. The event stream opens with a one-use ticket, since a browser's `EventSource` sends no header, and a page that is not signed in shows its sign-in first. Hiding parts of the open lists from a caller with no token was turned down: a list that leaks unless someone remembers to hide a field is the bug this closes.
- 2026-11-09: A shared backend's `.env` lives outside every folder the canopy and shells containers mount (`~/.config/canopy-deploy/env` on the mini and De Soto), and the checkout holds a link to it. The checkout is a repo canopy scans, so the file in it was one any `operate` caller could fetch and any shell could read. compose on the host follows the link; in a container it leads nowhere. A canopy shell's redeploy reads the host's address from `~/.ssh/canopy_deploy_host` instead (docs/deploy.md, "Where `.env` lives").
- 2026-11-10: The Mac's server keys (voice, GPT-Live, transcribe) live in the credentials bundle, and the launchd agent runs `scripts/mac-server.sh`, which exports them and then becomes the server. A plist is copied whole at every edit and printed whole by `plutil -p` and `launchctl print`, so keys in it spread to backups and into tool output. Settings that are not secret stay in the plist (docs/deploy.md, "Voice").
- 2026-11-10: `bun run redeploy` takes a backend's name on the Mac (`mini`, `desoto`, `all`), and a host with no `mac` remote pulls from its origin. After a deploy the Mac names each backend left alone that runs another commit. The script reached only the mini before, and De Soto, updated by hand, fell behind.
- 2026-11-10: The secrets service mounts the folder of a shared backend's own `.env` at its host path, as a sink root and an import source, in place of the file alone, read-only. A key rotated on the gate page reached the Mac's copy and never the mini's. The canopy and shells containers still see neither, and a written value takes effect at the next `bun run redeploy --restart`.
- 2026-11-10: The import reads a dotenv file line by line and skips what is not `KEY=value`, because one stray line made a whole file read as empty. On a reader such a file can be a sink: canopy rewrites the lines of its own keys and carries the rest byte for byte. Turning the odd lines into comments was the first plan and would have broken `_control` and the sudoku deploy scripts, which read some of them in `~/dev/.env` by their labels. On the mini a sink stays strict, since its files are compose env files.
- 2026-11-10: Waiting proposals are kept in `proposals.json`, still sealed, because every deploy that rebuilt the secrets image dropped them without a word.
- 2026-11-10: A machine key's passphrase needs 8 characters, down from 12, by Eric's choice: he types it after every Mac canopy start. scrypt at 2^18 and the key file's 0600 mode are what stand behind it.
- 2026-11-10: A Mac's key passphrase can wait in the login Keychain between starts, only when its owner runs `canopy secrets unlock --keep`. The 2026-10-14 passphrase exists so an agent running as the same user cannot open the key, and any such process can read that Keychain item with no prompt, so the keep is never a default, says what it gives up, and `canopy secrets forget` undoes it. The Mac's server restarted four times in one session that day, and each restart locked the key.
- 2026-11-10: A reader says when the store does not seal to its open key (`keyUnlisted`), and `canopy secrets status` exits 1 on it. A key replaced and unlocked read "open" while no sink of the machine could be written.
- 2026-11-10: A machine's new recipient reaches the gate page in the fragment of a link from the machine's own page, and it only fills the machine-key form. A stored key proposal approved with one tap was dropped, because any holder of the Mac's token could have queued its own key for the store to seal to.
- 2026-11-10: A scan leaves out a value its file's sink already keeps in step. 149 of the 407 proposals waiting that day were such no-ops.
- 2026-11-10: The clock view adds no route and no state. It reads the schedules the page already holds and writes through the routes each thing already had, so `triggers.json` stays a file written by hand and a schedule rule can be fired from the view but not changed there. The backend's time zone is worked out from the `next` it already sends, not sent.
- 2026-11-11: A stage's claude can sign in with a token from `claude setup-token`, kept as `oauth-token.txt` in the runner's own claude folder on the host (`~/.config/canopy-stages/claude`, `~/.config/canopy-coord/claude`) and read by the runner at each hello and each claude start. A `/login` made in the container lapses about 30 days after it was made, used or not, and the mini's had been dead for ten days when every new project parked on "OAuth session expired". The token is a file and not a compose env name, because compose names no secret for stages, and it is the stages' own, never the host's. The hello says the login's state and never the token. A dead login holds the queue while any stage uses Claude, and a project starts on its own once the login is back or routing no longer needs it (docs/deploy.md, Stages, step 7).
- 2026-11-11: `bun run stage-token [mini | desoto | here] [stages | coord | all]` mints that token and saves it on the backend's host in one command, the browser's "Authorize" the only step left to a person. `claude setup-token` only prints, so three tokens minted by hand that day were saved nowhere. The script shows a mask where claude prints the token, checks the token with one turn before saving, and sends it to the host on ssh's stdin, never as an argument.
- 2026-11-11: A backend with nowhere to run a stage refuses a new project (409) instead of keeping it queued for good. The Mac held one that way with nothing on the page saying why.
- 2026-11-11: On a seed, a run that ends in an error parks its flow at that step, and a resume runs that one step again. A failed flow there made the incubator start the whole stage over. Other repos keep the old rule, where a fleet or a trigger waits on the flow's end.
- 2026-11-11: A retry by hand at a gate that refused the work goes back to the step the workflow names as `back`, with the reason and the refusing step's closing words. Continue still passes the gate, because overriding a judge is the user's call, and its button now says "anyway" and comes second.
- 2026-11-11: The ship puts a repo's and a Vercel project's name on the project's record before asking for it. A later try takes up what is under that name only when it is as a cut-short try left it: a private, empty repo, or a project with no deployment. Anything else is left alone and the next name is used.
- 2026-11-11: Plugins are installed, turned on and off and removed only through each agent's own CLI on its machine, never by canopy writing their files, because claude keeps `settings.json`, `installed_plugins.json` and its cache in step and a hand edit would leave them apart. A machine that reads dotclaude's shared `settings.json` refuses an op that would change it there, and the page sends the op to the machine kit.json marks `commits: true`: an unstaged edit to a tracked dotclaude file on the mini stopped its pulls for three weeks (2026-10-20 to 2026-11-11). Codex has no plugin toggle in its CLI, so canopy offered none for it at first.
- 2026-11-11: Codex's switch is the one plugin change canopy writes itself: the `enabled` line in the plugin's own `[plugins."id"]` table in `config.toml`, the same line codex writes when it installs a local plugin. The edit swaps in a copy that keeps the file's mode, only when nothing wrote the file meanwhile, and stays only when `codex plugin list` then reports the new state; otherwise the old bytes go back. Canopy never adds a table, since a second one for the same plugin stops codex reading its config at all, and offers no switch for a plugin the ChatGPT account brings (its list source is remote), because a table does nothing for those (both checked against codex on 2026-11-11).
- 2026-11-11: The plugins view commits dotclaude's `settings.json` on the machine kit.json marks `commits: true`, from a button on that machine's line, after showing what the commit holds by key name only, because `settings.json` can hold secrets in `env`. The commit holds that file alone and runs only on the bytes that were shown. A push turned away is rebased onto the remote and sent again only while no other tracked file in dotclaude is changed; otherwise the commit stays local, the page says the push failed, and the machine's line counts the dotclaude commits not pushed until they are, so a conflict never leaves the checkout every machine pulls from mid-rebase.
